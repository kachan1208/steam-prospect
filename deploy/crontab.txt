# Prospect droplet crontab — THE DEPLOYED ARTIFACT, not documentation.
#
# Install:  crontab /root/prospect/deploy/crontab.txt   &&  crontab -l | head
# Verify :  crontab -l | diff - /root/prospect/deploy/crontab.txt && echo in-sync
#
# RECONCILED AGAINST THE LIVE BOX 2026-08-29 (`crontab -l`). The previous version of this
# file was reconstructed from script comments and differed from reality in three ways that
# would each have caused harm on install:
#
#   1. It DROPPED `systemd-run --scope -p MemoryMax=1500M -p MemorySwapMax=0` from the two
#      keepers and the quiet window. Those caps are not decoration: this box has 3.9GB, the
#      socials keeper has been observed leaking to 3.2GB, and an unbounded keeper OOM-kills
#      whatever else is running. Installing without them would have removed the fix that a
#      previous outage bought. They are preserved verbatim below.
#   2. It carried an 05:00 twitch collector. There is NO twitch line on the live box — the
#      creator vertical was retired product-wide (the mart, the dashboards and the source
#      table are all gone), so the job was correctly deleted at some point and must not be
#      resurrected. Dropped.
#   3. It scheduled the light build at 13:00; the box runs it at 13:30. Live time kept.
#
# PATHS POINT INTO THE GIT CHECKOUT (/root/prospect/deploy/...). Every script resolves its
# helper as "$(dirname "$0")/lib.sh", so running from the checkout is correct — and it makes
# `git pull` the whole deploy for shell changes, which removes the /root copy that used to
# drift from the repo (the copy at /root/prospect-refresh.sh is now unused; delete it once
# you have seen one clean nightly from this file).
#
# Everything runs under cron-wrap.sh, which takes the lock nonblocking and pushes
# prospect_pipeline_step_success{step="<job>"} for the job. That is what makes a job
# MONITORED: alert_check.py's headline check is "any step_success == 0 in the last 24h", and
# before wrapping, only the nightly and the light build pushed that series at all — a repeat
# of the "22 of 26 nightlies failed silently" incident on any other job would still have been
# silent. A skipped run (lock held) pushes prospect_cron_skipped and exits 0.

SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

# ── 21:00 UTC — the nightly: scrape lanes, ETL, validate, swap the mart, restart the app.
# Owns /root/.prospect-refresh.lock for its whole life (3-6h), which is what keeps the
# daytime keepers out of the ETL's way.
0 21 * * * /root/prospect/deploy/cron-wrap.sh nightly_refresh /root/prospect/deploy/prospect-refresh.sh

# ── 06:00 UTC — daytime review-coverage keeper. Deepens sampled review TEXT toward
# min(true_total, 20k) for every 50+-review game. 13h timeout ends before the 21:00 nightly;
# takes the refresh lock so it cannot overlap a still-running one. Self-draining: exits in
# seconds once coverage is full (which is why the box is often idle inside this window).
0 6 * * * /root/prospect/deploy/cron-wrap.sh review_keeper bash -c 'cd /root/steam-scraper && timeout 46800 systemd-run --scope --quiet -p MemoryMax=1500M -p MemorySwapMax=0 /root/steam-scraper/.venv/bin/python -m steam_scraper.scraper --db /root/steam-scraper/steam_games.db deepen-reviews --target 20000 --min-reviews 1 --activity-months 240 --refresh-days 7 --limit 15000 --workers 16 --rate 8.0' >> /root/deepen_backfill.log 2>&1

# ── 06:15 UTC — daytime socials keeper. OWN lock, deliberately: it must run ALONGSIDE the
# review keeper (different endpoints — store pages vs appreviews), so it must not contend for
# the refresh lock. This is the job observed leaking to 3.2GB; the MemoryMax is load-bearing.
15 6 * * * /root/prospect/deploy/cron-wrap.sh -l /root/.prospect-socials.lock socials_keeper bash -c 'cd /root/steam-scraper && timeout 46800 systemd-run --scope --quiet -p MemoryMax=1500M -p MemorySwapMax=0 /root/steam-scraper/.venv/bin/python -m steam_scraper.scraper --db /root/steam-scraper/steam_games.db dev-socials --min-reviews 0 --refresh-days 90 --limit 60000 --workers 8 --rate 2.0' >> /root/dev_socials_keeper.log 2>&1

# ── 13:30 UTC — midday light mart build: every mart except the two full-text monsters, which
# are copied from the published mart. Makes a data/code fix visible in ~30min instead of at
# the next nightly. Takes the refresh lock, so it skips itself if any build is running.
30 13 * * * /root/prospect/deploy/cron-wrap.sh light_build /root/prospect/deploy/light-build-cron.sh

# ── 19:15 UTC — quiet-window writers (tags_refresh, refresh_released, review_histogram),
# serial, in the 19:00-21:00 gap: all three lost the SQLite write race in the contended
# nightly lanes. quiet-window.sh enforces ONE absolute deadline across the three steps —
# the old inline `timeout 6000 bash -c 'timeout A; timeout B; timeout C'` could not, because
# each inner timeout escapes the outer's process group, so an orphaned step could keep
# holding the refresh lock past 21:00 and cost the entire nightly. The systemd scope is kept
# from the live entry so the three scrapers stay memory-capped.
15 19 * * * mkdir -p /var/log/prospect-steps && /root/prospect/deploy/cron-wrap.sh quiet1915 systemd-run --scope --quiet -p MemoryMax=1500M -p MemorySwapMax=0 /root/prospect/deploy/quiet-window.sh >> /var/log/prospect-steps/quiet1915.cron.log 2>&1

# ── 19:30 UTC — backups. OWN lock: it must not be blocked by, or block, the refresh lock.
# Placed after the quiet window and before the 21:00 nightly. signals.db (follower + price
# series) and refresh_history.json daily; steam_games.db on Sundays. These series are
# forward-only and can never be backfilled, which is the whole reason this job exists.
30 19 * * * /root/prospect/deploy/cron-wrap.sh -l /root/.prospect-backup.lock backup /root/prospect/deploy/backup.sh >> /var/log/prospect-backup.log 2>&1

# ── every 30 min — evaluate the metrics everything above pushes, and notify on breach.
# Inert until /root/.prospect-alerts.env exists with NTFY_TOPIC and/or WEBHOOK_URL; it exits
# non-zero and logs loudly rather than pretending to be armed.
*/30 * * * * /root/prospect/deploy/observability/alert_check.py >> /var/log/prospect-alerts.log 2>&1
